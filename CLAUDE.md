## Coding values

* Null safety, data integrity, & exhaustiveness through defensive programming
* Creating ergonomic APIs with pits of success & the principle of least surprise
* VSA - grouping by feature/use-case before technical layer
* YAGNI & KISS

## Documentation values

When commenting & documenting, write as close to the code as possible:

1. In-line comments
2. Docblocks
3. Directory-scoped `CLAUDE.md`
4. Last resort: application-scoped files in the repo's `docs/` dir

Write only as much as a skilled dev would need to get up to speed - no need to waste a future-reader's time with something they already know or can trivially find out.

## Design values

* Research, and plan, but be willing to change your plans - what sounds good "on paper" may not work in practice
* Take a fail-fast approach; iterate your way to success
* Build tools and debugging features that help you visualize and validate your work
